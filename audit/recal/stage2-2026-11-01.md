## 3. Pool check

**A crash, fixed.** The first `--calibrate all` (defaults) aborted with rc=134 after the within-tier part: a worker
thread overflowed its 256 MB stack at the start of the tier ordering (t1 decks into t0). gdb (`--calibrate ordering
--pool t1`) showed `t12_isshin::ascension_attack` -> `run_hook` -> `ascension_attack` ... without end, under
`t0_anikthea::anikthea_copy`. Anikthea (t0) makes 3/3 Zombie creature copies of enchantment cards, so an attacking
creature could be a Firebender Ascension. `atk_trigs` counted that creature's own Ascension hook as an attack
trigger, and from four quest counters the Ascension "copied" it by rerunning its own hook. By the Oracle text, the
Ascension's quest trigger is its own ability and is not caused by the creature attacking. Fix 3b63138f:
`atk_trigs` skips a Firebender Ascension's own hook (with a test, `cards_t12_isshin.rs::an_attacking_creature_firebender_ascension_does_not_count_itself`;
suite 3810 passed, 0 failed; build without warnings). The fix can only change games where Isshin's Ascension meets
Anikthea (t1 into t0 ordering); identity: the fixed binary = the step-2 binary byte for byte on `--realism` t0 and t1
(300 games), so steps 1-2 stand. Every step-3 run below uses the fixed binary.
